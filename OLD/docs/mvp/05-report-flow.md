# Report Flow

## Reporting Question

A manager asks:

"What did you do between June 24 and July 24?"

Work Memory should answer from preserved context, not from memory reconstruction.

## Behaviour

The user chooses the date range:

June 24 to July 24.

Work Memory gathers context evidence captured inside that range.

The answer should organize work by context, not by container.

## What Work Memory Should Produce

The report should include:

- Contexts touched during the period.
- What changed in each context.
- Decisions made.
- Blockers discovered or resolved.
- Open questions.
- Resume points.
- Important supporting evidence.
- Days with meaningful activity.

## Ordering

The report should appear in this order:

1. Summary of the period.
2. Contexts with meaningful progress.
3. Decisions and outcomes.
4. Blockers and unresolved questions.
5. Work that needs follow-up.
6. Supporting chronological evidence.

## What The Report Should Avoid

The report should not be:

- A raw activity dump.
- A timer export.
- A task list.
- A list of opened containers.
- A list of every captured sentence.

## User Review

The user should be able to review the answer before sharing it.

The product should not invent missing facts. If the preserved context is incomplete, the report should show the gap instead of pretending certainty.

## Reporting Standard

The report is successful when the user can answer the manager without searching every container or reconstructing a month from memory.
