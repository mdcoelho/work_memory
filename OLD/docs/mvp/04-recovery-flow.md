# Recovery Flow

## Scope

Recovery means returning to a context with enough continuity to continue, explain, or decide.

The product should show what matters first, not everything first.

## After 30 Minutes

The user still has partial memory.

The product should show, in order:

1. The most recent captured evidence for the context.
2. The last resume point.
3. Any open question, blocker, or decision.
4. Recent related captures from today.

Why: after 30 minutes, the user needs a quick reminder, not a full history.

## Tomorrow

The user remembers the broad shape but not the exact state.

The product should show, in order:

1. Current context summary.
2. What changed yesterday.
3. Decisions made.
4. Open blockers or questions.
5. Resume point.
6. Related evidence from the previous day.

Why: tomorrow's recovery requires rebuilding state, not only remembering the last note.

## After 3 Weeks

The user should not be expected to remember the context.

The product should show, in order:

1. What this context is.
2. Why it mattered.
3. People, organizations, products, problems, or artifacts involved.
4. Key decisions and reasons.
5. Open questions and unresolved blockers.
6. Last meaningful state.
7. What changed most recently.
8. Safest resume point.
9. Supporting evidence.

Why: after 3 weeks, recovery requires orientation before detail.

## What The User Should Not Need To Remember

The user should not need to remember:

- The old name of the context.
- Which artifact triggered the work.
- Which container held the last evidence.
- Why a decision was made.
- What options were rejected.
- Where the work stopped.
- Whether the context was paused, split, merged, or resolved.

## Recovery Standard

Recovery succeeds when the user can continue work without reconstructing the context from scattered evidence.
