# First Screen

## Scope

This document describes behaviour only.

## Purpose

The first screen exists to answer one question:

Where is my work memory right now?

It should orient the user without forcing organization.

## Information Visible

The user should immediately see:

- The most recent captured context evidence.
- Active contexts from today.
- Contexts with unresolved resume points.
- Decisions or blockers captured today.
- The last meaningful state before the most recent interruption.

This information appears because the user usually opens the product to continue, capture, review, or explain work.

## Actions Possible

The user should be able to:

- Capture new context immediately.
- Reopen a recent context.
- Review today's context trace.
- Search or filter by date range when reporting is needed.

No other action is required for MVP.

## What Should Not Happen

The first screen should not ask the user to:

- Choose a project.
- Choose a folder.
- Classify work.
- Create a task.
- Start a timer.
- Configure a workflow.
- Clean up old entries.

## Behavioural Reason

The first screen must reduce recovery cost.

The user is often arriving after an interruption. The product should make the current memory state obvious and make capture immediate.
