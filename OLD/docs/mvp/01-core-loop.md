# Core Loop

## Scope

The MVP has one user loop.

The user opens the product, captures work, returns to work, reviews the day, and reports work.

Nothing else belongs in the core loop.

## 1. Open

The product opens directly into the user's current work memory.

The user should immediately understand:

- What was recently captured.
- Which contexts are active today.
- Which contexts have unfinished state.
- Where the last work stopped.

The product should not ask the user to configure, classify, plan, or choose a structure before work can continue.

## 2. Capture Work

The user captures the current context before it disappears.

Capture should preserve:

- What is happening.
- Why it matters, if known.
- The context it seems to belong to, if obvious.
- Any decision, blocker, question, change, or resume point.

The capture can be rough. The goal is continuity, not polish.

## 3. Return To Work

After capture, the user goes back to the original work immediately.

The product should not keep the user inside management, review, classification, or cleanup.

The successful capture moment feels like placing a marker in memory and leaving.

## 4. Review The Day

Later, the user reviews the day by context.

The day review should help answer:

- Which contexts moved today?
- What changed?
- What decisions were made?
- What remains unresolved?
- Where should each context resume?

The review should not become planning, task grooming, or time tracking.

## 5. Report Work

When asked what happened, the user reports from preserved context.

The report should explain completed work, decisions, blockers, changed contexts, and unresolved state across a date range.

The report should not require the user to rebuild the day from memory.

## Loop Standard

If a behaviour does not help this loop, it is not MVP.
