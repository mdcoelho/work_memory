# Vision

## North star

Work Memory should become the fastest way for the founder to preserve and recover context.

The product is not trying to become a better task manager, work log, notes system, or timer. It is trying to solve a different problem: preserving the identity of a context across interruption and time.

When the founder returns after an interruption, Work Memory should help answer:

- What context am I returning to?
- Why did it matter?
- What changed?
- Which relationships define it?
- Where should it resume?
- What should I be able to explain later?

## Desired founder outcome

The founder should end the day with recoverable contexts, not just a list of unfinished obligations or a chronological activity record.

A good Work Memory helps the founder understand progress, reconstruct decisions, prepare updates, and restart work without rebuilding the relationships between customers, suppliers, products, problems, artifacts, meetings, and decisions.

The product should make the founder less dependent on memory and less anxious about losing context.

## Product stance

- Context should come before containers.
- Identity should be preserved even when names change.
- Relationships should matter more than hierarchy.
- Recovery should matter more than organization.
- AI should reduce cognitive load without interrupting the founder.
- Simplicity should win over configurability.

## Experience standard

Work Memory should feel faster than Things 3 for capture. Things 3 is the documented speed benchmark for the founder's capture experience.

The founder should be able to preserve a context before the thread disappears. If the product requires setup, classification, or workflow decisions before capture, it has failed the core experience.

The product should feel lightweight and direct. It should never feel like ClickUp, Jira, a CRM, or a wiki.

## Strategic boundary

Work Memory is a professional memory system for the founder's context-switching workday.

It can help notice obligations inside context, but it should not manage work as tasks, statuses, or workflows. Its primary value is preserving context identity from real work.
