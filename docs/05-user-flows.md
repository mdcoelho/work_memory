# User Flows

## Purpose

These flows describe the product behavior at a product level. They are not implementation requirements.

Each flow protects the same rule: capture first, organize later.

## Flow 1: Capture during interruption

The user is working, gets interrupted, and needs to preserve context before switching away.

Expected outcome:

- The user creates an entry in seconds.
- The entry preserves enough context to recover later.
- The user is not forced to classify, schedule, assign, or structure anything.

This is the most important flow. If this flow is slow, the product fails.

## Flow 2: Resume after context switch

The user returns to work after time away.

Expected outcome:

- The user sees recent entries in a Work Log.
- The user can understand what happened and why it mattered.
- The user can restart without reconstructing context from memory.

## Flow 3: Reconstruct the day

The user wants to understand what they actually did.

Expected outcome:

- The Work Log shows the substance of the day.
- Entries help the user remember decisions, progress, blockers, and shifts in attention.
- The user can prepare a truthful update without relying on timers.

## Flow 4: Organize later

The user decides that some entries need structure.

Expected outcome:

- Classification happens after capture.
- Structure is optional and useful, not required.
- The user can improve recall without turning Work Memory into a project management system.

## Flow 5: Use AI assistance

The user asks for help reducing cognitive load.

Expected outcome:

- AI summarizes, clarifies, or classifies existing context.
- AI does not interrupt capture.
- AI suggestions remain subordinate to the user's memory.
