# Product DNA

## Research status

This document records the original product philosophy as a hypothesis.

It is not user evidence. Read it with [Research Opportunities](research/06-opportunities.md) and [User Pains](research/02-user-pains.md) before treating any principle as a decision.

## Why this product exists

Modern knowledge workers lose context because work rarely happens in a straight line.

Their day is fragmented by meetings, messages, documents, decisions, urgent requests, and unfinished thoughts. They move between contexts before the previous context has been captured.

The result is not only missed tasks. It is lost professional memory: what happened, why it mattered, what changed, and where work should resume.

Work Memory exists to preserve that context with as little effort as possible.

## The problem

People remember what they have to do.
They don't remember what they actually did.

This creates friction every time they return after an interruption. They must reconstruct their own activity from memory, chats, files, calendars, and task lists.

That reconstruction is slow, incomplete, and mentally expensive. The problem is expanded in [Problem Statement](02-problem-statement.md).

## Vision

Build a Work Memory, not a task manager.

A task manager organizes future commitments. Work Memory preserves professional context so users can understand what happened, recover momentum, and explain their work.

The product should feel like a fast memory layer: always available, easy to capture into, and useful when the user needs to resume, explain, decide, or hand off work. The long-term direction is described in [Vision](01-vision.md).

## Principle hypotheses

- Capture in seconds.
- Organize later.
- Context is more important than folders.
- AI reduces cognitive load.
- Classification can happen later.
- Work Logs are more important than timers.
- Entries are the basic unit of memory.
- The application should not feel bureaucratic.
- Every interaction should save time.

## Boundary hypotheses

It is not:
- Jira
- ClickUp
- Notion
- CRM
- Wiki
- Project management software

Boundary hypothesis: Work Memory should not become another ClickUp or Jira. It should not optimize for process administration, complex workflows, status management, or team bureaucracy.

Hypothesis: the purpose of Work Memory is to become the user's professional memory.
