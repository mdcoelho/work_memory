# Vision

## North star

Work Memory should become the fastest way for the founder to preserve and recover professional context.

The product is not trying to become a better task manager. It is trying to solve a different problem: helping the founder remember what happened across a fragmented workday.

When the founder returns after an interruption, Work Memory should help answer:

- What was I doing?
- What changed?
- Why did it matter?
- Where should I resume?
- What should I be able to explain later?

## Desired founder outcome

The founder should end the day with a useful record of work, not just a list of unfinished obligations.

A good Work Memory helps the founder understand progress, reconstruct decisions, prepare updates, and restart work without searching across Outlook, Odoo, Fusion, documents, and memory.

The product should make the founder less dependent on memory and less anxious about losing context.

## Product stance

- Capture should be faster than organization.
- Context should be more important than folders.
- Work Logs should be more useful than timers.
- AI should reduce cognitive load without interrupting the founder.
- Simplicity should win over configurability.

## Experience standard

Work Memory should feel faster than Things 3 for capture. Things 3 is the documented speed benchmark for the founder's capture experience.

The founder should be able to create an entry before the thought disappears. If the product requires setup, classification, or workflow decisions before capture, it has failed the core experience.

The interface should feel lightweight and direct. It should never feel like ClickUp, Jira, a CRM, or a wiki.

## Strategic boundary

Work Memory is a professional memory system for the founder's context-switching workday.

It can help notice obligations inside context, but it should not manage work as tasks, statuses, or workflows. Its primary value is preserving useful context from real work.
