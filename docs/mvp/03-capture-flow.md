# Capture Flow

## Target

Capture must take less than 5 seconds.

The user should never be forced to classify during capture.

## Fastest Possible Flow

1. User opens capture.
2. User writes the minimum useful memory.
3. User saves.
4. User returns to work.

That is the whole capture flow.

## What The Capture Must Preserve

The capture should preserve enough context to recover later:

- What is happening.
- Why it matters, if the user knows.
- What changed.
- What decision, blocker, or question exists.
- Where to resume.

The user can write any of these in plain language.

## What Is Optional

The following can happen after capture, but never during required capture:

- Naming the context.
- Renaming the context.
- Connecting the entry to an existing context.
- Adding people, products, suppliers, customers, or artifacts.
- Marking a decision, blocker, or open question.
- Cleaning up wording.

## What Is Forbidden During Capture

The product must not require:

- Classification.
- Project selection.
- Folder selection.
- Status selection.
- Priority selection.
- Timer start.
- Assignment.
- Required fields beyond the captured memory.

## Capture Quality Standard

A messy capture is successful if the user can recover the context later.

A perfect capture is a failure if it slows the user enough that the context is lost.
