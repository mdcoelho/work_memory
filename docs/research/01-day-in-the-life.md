# Day in the Life

## Evidence base

These field notes synthesize repository evidence about the first target user: the project founder.

The founder owns many parallel workstreams across clients, teams, suppliers, operational questions, and responsibilities. The strongest source documents are [Founder Profile](../03-personas.md), [Problem Statement](../02-problem-statement.md), [Product DNA](../00-product-dna.md), and [Mental Model](../04-mental-model.md).

## Observed workday

The founder changes professional context many times during the day.

The founder moves between Outlook, Odoo, Fusion, meetings, supplier questions, management questions, documents, decisions, urgent requests, operational questions, unfinished thoughts, and partially completed work. The workday does not run as one continuous thread. It runs as a sequence of interrupted work fragments.

The founder carries several workstreams at once. Each workstream has its own client, team, responsibility, decision history, and unfinished state.

## Starting work

The founder begins work with context already distributed across several places:

- Calendar.
- Outlook.
- Odoo.
- Fusion.
- Supplier conversations.
- Management questions.
- Files.
- Documents.
- Task lists.
- Notes.
- Memory.

The founder does not only need a list of obligations. The founder needs to recover what was happening before the next work fragment begins.

## During active work

The founder holds transient context in memory while working:

- What changed.
- What was tried.
- What was decided.
- What blocked progress.
- Why direction changed.
- What must be remembered when returning later.

This context is valuable and fragile. It disappears when the founder switches away before recording it.

## Interruption pattern

The founder is interrupted by meetings, messages, urgent requests, documents, decisions, and operational questions.

The interruption cost is not only time. The interruption breaks the chain between work, reasoning, and memory.

The founder often moves into another workstream before the previous one has been captured.

## Switching pattern

The founder changes from one professional context to another before the previous context has been externalized.

The task itself can survive the switch. The surrounding meaning gets damaged:

- Why the work stopped.
- What had just changed.
- What decision was forming.
- What reasoning mattered.
- Where to resume.

## Returning pattern

The founder reconstructs context from scattered sources when returning to work.

The reconstruction path crosses Outlook, Odoo, Fusion, calendar, files, documents, task lists, notes, and memory. This is slow because each tool contains only part of the story.

The founder uses reconstruction to resume work, explain progress, prepare handoffs, and report what happened.

The detailed case version of this day is documented in [Real Day](../cases/01-real-day.md).

## End-of-day pattern

The founder can be productive and still struggle to reconstruct the day with confidence.

The central memory failure is not forgetting every future task. The central memory failure is losing the record of what actually happened.

Completed work matters more than future planning in this context because the founder must explain work performed, recover decisions, and understand progress across shifting workstreams.

## Classification behaviour

The founder delays classification because the interruption cost is higher than the value of perfect structure at capture time.

The repository repeatedly favors capture before organization. This reflects the founder's work rhythm: capture must happen while context is still alive; classification can happen when the work fragment has stabilized.

## Time and duration behaviour

The founder values Work Logs over timers.

The repository treats timers as duration records and Work Logs as meaning records. The founder needs context, progress, and reasoning more than elapsed time alone.

## Cognitive load

The founder experiences cognitive fatigue from context switching.

The fatigue comes from holding too many open threads in memory, reconstructing prior work, and repeating thinking when context was not captured.
